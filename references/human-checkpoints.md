# 人机介入与决策界面

设计方向选择、Review、纠偏、知识补充或批准时，完整读取本文件。

## 核心原则

人类介入不是自动化失败，但也不是越多越安全。模型先完成能够通过材料、检索和推理自行完成的工作，只在模型无法替用户决定的高价值节点介入。

每个交互先回答：

> 用户此刻究竟要做什么决定？

页面和对话只展示做出这个决定所需的信息。系统拥有的字段不等于用户需要看到的字段。

## 人工介入价值测试

至少一个条件成立才设置 Checkpoint：

- 不同选择会改变商业、创意或技术方向；
- 决定依赖用户独有的目标、价值、风险偏好或组织知识；
- 准备改变范围、预算、受众、承诺或不可逆状态；
- 材料存在无法通过继续检索解决的冲突；
- 准备把工作假设升级为正式主张；
- 需要用户审阅模型最终要代表用户交付的完整内容。

不设置 Checkpoint：

- Brief 或已有材料已经回答；
- 模型可继续查资料解决；
- 只是检查格式、文件存在或机械分类；
- 反馈不会改变下游行为；
- 只是为了证明流程里“有人审过”。

## 先做再问

进入人工交互前，模型先：

1. 阅读相关材料；
2. 汇报当前理解、关键张力或候选判断；
3. 说明为什么剩余问题无法自行决定；
4. 只提出会改变后续方向的问题。

不要把资料摘要任务转嫁给用户，也不要重复询问材料已明确的背景。

## 交互信息预算

```text
Decision：用户此刻决定什么？
Show：做决定所需的最少信息是什么？
Hide：哪些日志、ID、来源路径和工程字段应折叠？
Ask：一个聚焦问题，或确实互斥的少量选项。
Default：哪些低风险操作可以默认？
No default：哪些实质判断必须明确选择？
Effect：反馈具体改变哪个产物或下一步？
```

复杂内容审阅时，核心内容完整展示，工程信息折叠；“最少信息”不是把被审内容压缩成摘要。

## 默认行为

可以默认：

- 可逆、低风险的操作状态；
- 批量页面的“通过”状态；
- 展开/折叠、排序和保存路径；
- 不改变语义的界面偏好。

不能默认：

- 战略方向；
- 合并到哪个对象；
- 范围、预算、承诺与风险；
- 把工作假设升级为正式结论；
- 不可逆安装、发布或外部写入。

用户输入修改意见时，应自动切换为“需要修改”。默认状态用于减少点击，不能替用户完成实质判断。

## 选项与推荐

- 只有候选已经清晰且互斥时才使用 2–3 个选项；
- 探索期展示当前理解和主要张力，提出开放但聚焦的问题；
- 模型提出的选项不是全部可能性，允许用户补充新方向；
- 只有低风险、可逆且有充分事实依据时才推荐默认选项；
- 对价值选择说明取舍，不替用户作出决定。

## Checkpoint 模板

```markdown
## Human Checkpoint：[名称]

Decision：
- [用户此刻决定什么]

Why human：
- [为什么模型无法替代]

Before asking：
- [模型先完成什么]

Show：
- [核心内容或关键差异]

Hide：
- [折叠的工程信息]

Ask：
- [一个问题或确实互斥的选项]

Default / No default：
- [界面默认与必须明确决定的内容]

Save to：
- [真正消费反馈的状态或产物]
```

反馈不必自动写入 Contract。只有下游机器需要解析或必须绑定版本时，才保存为结构化反馈 Contract。

## Review 形式

| 决定 | 形式 |
|---|---|
| 一个简单且明确的选择 | 聊天短问 |
| 中等复杂度内容 | Markdown 或表格 |
| 多个完整内容项 | HTML Review |
| 需要图片、结构化反馈或版本绑定 | 可保存反馈的 HTML Review |

使用本 Skill 的 `assets/review-page-template.html` 前，必须先替换其中的 Decision、核心内容和反馈去向。不要把通用占位页直接当成正式审阅。

**交付前还要把设计令牌内联进去**，否则页面会**没有任何样式**（而且不报错）：

```bash
python3 <planners-review-core>/scripts/inline_review_tokens.py <你的审阅页.html>
```

模板里留的是 `/*__DSH_TOKENS__*/` 占位符。表只有一份，在公共接缝 `planners-review-core/assets/dsh-tokens.css` ——
**不要把它复制进本 Skill**，那样改一次要同步三处，迟早漂移。
