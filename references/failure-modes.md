# 六种失败模式（减法与质量审计字典）

本文件沿用高杠杆概念词汇（Invisible Step 为流程场景特有扩展），在**里程碑 4（质检与减法审计）**时作为扫描字典，用于检查目标 Skill 是否存在结构缺陷与认知浪费。

---

## 1. Premature Completion（过早完成 / 伪完成）

- **含义**：模型在任务真正做好之前就宣布完成，注意力从“把当前核心质量做透”滑向“赶紧交差”。
- **常见信号**：
  - 缺乏具象的验收标准（KR / DoD），只写了“分析充分”、“润色得当”等虚浮形容词；
  - 遇到开放任务，模型输出了表面格式合规、但语义严重缺乏深度的半成品；
  - 缺少自动化校验工具，死逻辑全凭模型肉眼粗看。
- **防御机制**：
  - **设立清晰的 KR 与具象反例 (Negative Cases)**：让模型一眼看到“做到什么程度算砸了”；
  - **死逻辑交给确定性工具**：把可量化的格式、数据完整性交给脚本校验，脚本报错则阻断伪完成。

---

## 2. Duplication（真相源重复）

- **含义**：同一规则或逻辑出现在多个地方。重复不仅浪费宝贵的上下文，还会导致两处逻辑漂移，产生事实冲突。
- **常见信号**：
  - 一段数据清洗或正则逻辑，既在脚本里写了一遍，又在 `SKILL.md` Prompt 里详细写了一遍（两套真相源）；
  - `SKILL.md` 与参考文档把同一条业务规则解释了两次；
  - description 堆叠同义触发词。
- **防御机制**：
  - **确定性下沉**：既然脚本已经处理了死逻辑，Prompt 里只需保留一行调用说明，不要在提示词里重复业务规则；
  - 坚持单一真相源（Single Source of Truth），Prompt 中只保留指针。

---

## 3. Sediment（认知淤积 / 历史残渣）

- **含义**：旧版本逻辑、过期的调试脚本、废弃的临时规矩残留在 Skill 中。因为“添加容易、删除困难”，系统越来越重。
- **常见信号**：
  - `references/` 里有早已不被调用的说明文件；
  - `scripts/` 里有早期测试写的一次性脚本，无任何接口调用；
  - Prompt 里保留了大量“以防万一”的陈旧负面限制。
- **防御机制**：
  - **升级必须做减法 (Deletion Audit)**：每次重构必须执行删除测试，坚决拔掉无调用者的孤儿文件与死规则；
  - 依靠确定性校验脚本 `scripts/lint_skill.py` 自动扫描无路由的孤儿引用。

---

## 4. Sprawl（边界蔓延 / 模块臃肿）

- **含义**：Skill 过大、过散，把本该由模型自主推理的内容事无巨细写成上百条规则，严重挤占模型的上下文预算。
- **常见信号**：
  - `SKILL.md` 变成了几十页的 SOP 操作手册；
  - 把模型当成无知初学者，试图枚举所有可能的分支与边界细节；
  - 一个 Skill 试图兼顾多个互不相干的独立业务领域。
- **防御机制**：
  - **提取高杠杆概念词**：用 2~3 个精准的领域术语替代大段低密度说教；
  - **Playbook 启发式战术**：只给宏观应对策略，不搞穷举式规训；超大系统拆分为独立高内聚 Skill。

---

## 5. No-op（空操作 / 无效废话）

- **含义**：某行 Prompt 指令即使被删掉，模型的行为也完全不会发生任何改变，纯属浪费 Token。
- **常见信号**：
  - “请务必认真思考”、“一定要专业严谨”、“给出一份高质量答卷”等无意义套话；
  - 重复阐述模型预训练权重中早已熟知的通用常识。
- **防御机制**：
  - **No-op 删除测试**：对每句话做反思——删掉这句话，模型的行为真的会变差吗？如果不会，立刻删掉；
  - 弱形容词替换为**强核心概念**或**硬性确定性工具**。

---

## 6. Invisible Step（隐形步骤）

- **含义**：某个必经的关键业务动作，既没有在工作流中明确指出，也没有任何确定性脚本检查它是否发生。它不会报错，**它只是悄无声息地不发生**。
- **常见信号**：
  - 流程里默认“必须先做数据备份”，但没有任何一步触发备份命令，也没检查备份文件在不在；
  - 产物需要某个特定元数据，但全流程没有任何地方要求填入，最终交付物缺陷隐蔽。
- **防御机制**：
  - 全景工作流必须清晰呈现核心关键动作；
  - 关键产物通过确定性质检脚本做文件存在性与字段闭环校验，杜绝漏做。

---

## 减法审计核验清单（里程碑 4 使用）

在目标 Skill 交付前，对照本表进行逐项扫描：

```text
Failure Mode Scan
□ Premature Completion: 是否有具象的 KR、DoD 与反例卡住伪完成？
□ Duplication: 脚本与 Prompt 是否存在双重实现？是否存在两套真相源？
□ Sediment: 是否已彻底清理废弃脚本、孤儿 Reference 和失效旧规则？
□ Sprawl: 是否用高杠杆概念词进行了认知压缩？是否去除了微操 SOP？
□ No-op: 是否删除了所有“认真负责”类的废话指令？
□ Invisible Step: 关键必经动作是否有明确命令或脚本保障其必定发生？
```
